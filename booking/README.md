# DRIVE TIME — запис на уроки водіння

Окремий сайт на Render (не замінює Drive Ready UA). Вихідні файли у `booking/`.

## Сценарій учня
1. Відкриває сайт без реєстрації.
2. Обирає один із **загальних** для всіх користувачів вільних часових слотів.
3. Заповнює ім'я та телефон, погоджується на використання контактів.
4. Сервер PostgreSQL у транзакції перевіряє доступність і створює бронювання. Два учні не можуть підтвердити одну й ту саму годину: блокування на рівні PostgreSQL плюс унікальний індекс.
5. Після відповіді сервера показує дату, час, код бронювання та файл `.ics` для календаря. Немає непідтверджених обіцянок SMS або email.

## Кабінет інструктора
- `/admin.html` із паролем через змінну Render `ADMIN_PASSWORD`. Паролі ніколи не записують у GitHub.
- Перегляд активних та скасованих записів із телефоном, ім'ям, кодом і коментарем.
- Налаштування всіх семи днів тижня, зокрема **06:00–21:00**, за замовчуванням 60 хвилин.
- Тривалість уроку: 30, 45, 60, 90 або 120 хвилин.
- Вихідний або коротший робочий день на конкретну дату.
- Блокування вільних слотів (перерви); скасування записів із звільненням часу; експорт CSV.
- Зміни робочого графіка **не скасовують** підтверджені заняття автоматично. Інструктор має узгодити перенесення.

## Техніка й безпека
- Node.js + Express, PostgreSQL, всі API на тому ж домені.
- `DATABASE_URL` підключається через Render Blueprint `fromDatabase`.
- Всі персональні дані доступні лише через аутентифікований API, у публічному календарі лише `free/busy/blocked`.
- Серверні транзакції і унікальний індекс захищають від подвійного запису.
- HMAC-сеанс у HttpOnly Secure SameSite cookie, паролі й ключі лише у змінних оточення Render.
- Не надсилаються SMS чи email, не підключена оплата і не збирається геолокація.
- Публічний календар дозволяє запис у межах 60 днів, з 30-хвилинним запасом до початку уроку.
- Таймзона `Europe/Kyiv`.

## Важливо: тариф бази даних
Виділена база `drive-ready-bookings-db` у тарифі Render **Free**, який має обмежений строк існування (приблизно 30 днів). ПЕРЕД закінченням терміну необхідно змінити тариф або перенести дані в довготривалу базу. Не обіцяємо безстрокове збереження на безкоштовній БД. Адміністратору слід регулярно зберігати CSV як додаткову копію.

## Інфраструктура
Root blueprint: `render-booking.yaml`. Створюється лише **новий** вебсервіс `drive-time-booking`, а поточний `drive-ready-ua` не змінюється. База створена окремо як `drive-ready-bookings-db`.

Локальні тести: `cd booking && npm install && npm test`. Для локального запуску встановити `DATABASE_URL`, `ADMIN_PASSWORD`, `SESSION_SECRET`; без них сервер відмовляється запускатися.

**Після публікації** перевірити на справжньому HTTPS: `/health`, `/api/info`, `/api/days`, пробне бронювання в контрольованому середовищі, адміністраторський вхід, зміни графіка, скасування бронювання. Не створювати фіктивних реальних бронювань без потреби.
