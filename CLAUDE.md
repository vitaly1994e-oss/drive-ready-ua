# Обслуживание DRIVE READY UA и DRIVE TIME

- Делай изменения в отдельной ветке и открывай PR. Проверь статический сайт, браузерные сценарии и CI записи с изолированной PostgreSQL перед слиянием. Пользуйся синтетическими данными и не создавай тестовые записи в продакшене.
- Сохраняй украинский интерфейс, официальные ссылки, маршруты, тренажёры и сценарий записи. Для дорожных правил и материалов указывай официальные источники и даты проверки. Проверяй обе ширины экрана и доступность с клавиатуры.
- Храни строки подключения, пароли и ключи только в секретах окружения. Не помещай клиентские данные в Git и CI. Не меняй домены, платежи, тарифы и права доступа без согласия владельца. Не удаляй пользовательские данные.

## Проверки и выпуск

Выполни `python3 tests/validate.py`, `python3 tests/check_seo.py` и `npm --prefix booking test`. Полные сценарии запускаются в `.github/workflows/validate.yml` и `.github/workflows/booking-check.yml`. В CI записи зависимости устанавливаются через `npm ci`. Проверку двух рабочих сайтов запускай через `python3 tests/check_seo.py --live`. После слияния ежедневный мониторинг запускается в 05:41 UTC.

Render публикует два существующих сервиса из `main`: статический `drive-ready-ua` и `drive-time-booking-ov62` с корнем `booking` и проверкой `/health`. Сливай после зелёных проверок PR. Для автоматического барьера перед выпуском настрой **After CI Checks Pass** в обоих сервисах. Для сервиса записи используй `npm ci --omit=dev` как команду сборки после появления lockfile в `main`.

При регрессии используй предыдущий рабочий деплой нужного сервиса в Render → Events → Rollback, запусти публичную проверку и подготовь revert PR. Откат версии приложения не требует восстановления или очистки базы.

## Индексация

Подтверди владение двумя свойствами с URL-префиксом в Google Search Console и добавь их в Bing Webmaster Tools. Отправь собственный `/sitemap.xml` для каждого хоста. Если нужен IndexNow, размести отдельный публичный файл ключа в статическом корне каждого хоста и отправляй только изменившиеся канонические URL после успешной публикации. Не включай API, личные страницы записи и профиль с локальным прогрессом в sitemap. Не используй искусственный трафик или массовую отправку URL.
